## Quick card — อ่านก่อน label (2 นาที)

**คำถามเดียวที่ต้องตอบ: ถ้าฉัน *ทำตามที่ข้อความบอก* (โอน / กรอก / กด / แอด / โทรกลับ) ฉันจะเสียเงินหรือข้อมูลไหม?**
❌ ไม่ใช่ "ถ้าฉัน*ไม่*ทำตาม ฉันจะเสียอะไร" — โดนหักคะแนน/พลาดโปร ไม่ใช่ความเสียหายจากมิจฉาชีพ

| ตอบ | หมายถึง | ได้ค่านี้เมื่อ |
|---|---|---|
| `safe` | ทำตามได้ ไม่เสียอะไร | ข้อความไม่ได้ขอให้เสียเงิน/ข้อมูล-รหัส/ติดตั้งแอป/**เลขบัญชีของฉัน** |
| `danger` | อย่าทำ + แจ้ง 1441 | มีการขอ **และ** ข้อความมีสัญญาณจาก **รายการปิด 11 ข้อ** (ข้อ 3) อย่างน้อย 1 |
| `caution` | อย่าเพิ่งทำ จนกว่าจะเช็ค **X** | มีการขอ แต่ไม่มีสัญญาณ 11 ข้อ → **ต้องระบุ X** จากรายการ `needs_info` (ข้อ 4) เสมอ — caution ที่บอกไม่ได้ว่าต้องเช็คอะไร = ไม่มี |

**ทดสอบตัวเอง 3 ข้อก่อนเริ่ม** (ถ้าตอบต่างจากนี้ ให้อ่านข้อ 2 ก่อน):
- "ส่งงานด่วนนะครับ พรุ่งนี้อาจารย์ตรวจ" → `safe` (ทำตามแล้วไม่เสียอะไร แม้ไม่ส่งจะโดนหัก)
- "รหัส OTP ของคุณคือ 482913 ห้ามบอกใคร" → `safe` (ระบบ*ส่ง*ให้ ไม่ได้*ขอ*)
- "บัญชีถูกระงับ ยืนยันตัวตนที่ http://scb-verify.xyz" → `danger` (ขู่ + ให้แก้ด้วยลิงก์)

**กฎกติกา:** สมมติเสมอว่าผู้ส่งเป็นคนไม่รู้จัก · ตัดสินจากตัวข้อความเท่านั้น · ข้อความที่ต่างแค่ emoji/typo/ตัวยืด/คำต่อท้าย (inbox ได้, ทัก DM) ให้ verdict เดียวกัน · ข้อความ "เล่าเหตุการณ์" ("มีคนขอ… บอกว่าเป็น…") ให้ตัดสิน*สิ่งที่ถูกเล่า*

## 1. Verdict = สถานะการกระทำ (ไม่ใช่ความน่าจะเป็น)

ระบบนี้มีไว้บอกผู้ใช้ (รวมผู้สูงอายุ) ว่า **ตอนนี้ควรทำอะไร** ไม่ใช่ประเมินว่า "น่าจะเป็น scam กี่ %" ดังนั้น:

- `safe` ไม่ได้แปลว่า "ผู้ส่งเป็นคนดี" — แปลว่า *การทำตามข้อความนี้* ไม่ทำให้เสียอะไร ข้อความที่ยังไม่ขออะไร (เช่น "เปลี่ยนเบอร์ใหม่นะ") จึง safe แต่ระบบจะบอก `watch_for` (ข้อ 5) ว่าถ้าตามมาด้วยอะไรให้ระวัง
- `caution` = "รอข้อมูล" — ใน Q&A mode ระบบจะถามผู้ใช้ตาม `needs_info` แล้วตัดสินใหม่ใน turn ถัดไป; ใน ML mode = ส่งต่อไป Q&A (`suggest_qa`)
- `danger` = ข้อความนี้*เอง*มีกลไกหลอกครบ ไม่ต้องรอข้อมูลเพิ่ม — ถ้ายังอยากถามอะไรก่อนตัดสิน แสดงว่ามันคือ caution

**ห้าม:** danger เพราะ "ดูเหมือน SMS/มีลิงก์/ภาษาแปลก" · safe เพราะ "ภาษาสุภาพ/อ้างเป็นเพื่อน" · caution เพราะ "ไม่แน่ใจ" โดยบอก X ไม่ได้

## 2. Decision tree (3 คำถาม ทำตามลำดับ)

```
Q1  ทำตามที่ข้อความบอกแล้ว ฉันจะเสียอะไรไหม?  (เงิน / ข้อมูล-รหัส / ติดตั้งแอป-กดลิงก์ / โทรกลับเบอร์ที่ให้ /
    ให้เลขบัญชีของฉันแก่คนไม่รู้จัก)
    ├─ ไม่มีการขอเลย ......................................... safe  (+ watch_for ถ้าเป็น opener ข้อ 5)
    ├─ ขอแบบที่ฉันไม่เสีย ("ทัก DM" เฉยๆ, แนบ LINE ตัวเองในโพสต์ประกาศ/หาซื้อ) .... safe
    └─ ขอแบบที่ฉันเสีย (รวม "ขอเลขบัญชี/พร้อมเพย์ของฉัน จะโอนให้" — v2.1) ...... ไป Q2

Q2  ข้อความนี้*เอง*มีสัญญาณจากรายการปิด 11 ข้อ (ข้อ 3) ไหม?
    ├─ มี ≥ 1 .............................................. danger  (+ category ข้อ 6)
    └─ ไม่มี ................................................ ไป Q3

Q3  ก่อนทำตาม ต้องเช็คอะไร? เลือกจากรายการปิด 7 รหัส (ข้อ 4)
    └─ .......................................................... caution + needs_info: [...]
```

ข้อสังเกตที่คนมักพลาด:
- "ยืนยันข้อมูล / ยืนยันตัวตน / ส่งรหัส" แม้ไม่บอกว่าอะไร = **ขอ** (ฉันเสียข้อมูล) · "มีลิงก์ให้กรอก…" แม้ไม่เห็น URL = ขอ
- "สมัคร / ซื้อ" ลอยๆ ที่ไม่บอกช่องทาง ลิงก์ บัญชี = ยังไม่ขอ → safe — **ยกเว้น** "จอง" ของถูกจากคนไม่รู้จัก = ต้องมัดจำโดยนัย → caution (C03, v2.2)
- คำเร่ง (ด่วน, วันนี้เท่านั้น, เหลือชิ้นเดียว, หมดสิทธิ์), ราคาถูก, ชื่อแบรนด์, "ฟรี" — **ไม่ใช่สัญญาณ** ไม่เปลี่ยน verdict
- "รุ่นพี่ / แม่ / แอดมิน / แฟนเรา / ฝากบอก" = *คำอ้าง* ตรวจไม่ได้ → ไม่ทำให้ safe และไม่ทำให้ danger → ผลคือ Q3 (`verify_with_claimed_person`) — ยกเว้น "บัญชีนี้ของแฟน/คนอื่น" ที่เป็นสัญญาณ #2

## 3. รายการปิด: สัญญาณ danger (11 ข้อ — เพิ่ม/ลดต้อง bump version)

| # | สัญญาณ (ต้องครบในตัวข้อความ) | ตัวอย่าง | lexicon |
|---|---|---|---|
| 1 | **ขอ** OTP / รหัสผ่าน / PIN / รหัสยืนยัน / เลขบัตร ผ่านแชท ไม่ว่าอ้างเป็นใคร | "แอดมินกลุ่มขอรหัสยืนยัน" | credential_request |
| 2 | ปลายทางเป็นบัญชี**คนอื่น** / ชื่อไม่ตรงผู้ขาย (ผู้ส่งบอกเอง) | "บัญชีนี้ของแฟนเรา ปลอดภัยแน่นอน โอนมาเลย" | money_request: third_party_account / account_name_mismatch |
| 3 | จ่ายเงิน หรือ ให้ข้อมูล **ก่อน** เพื่อ "ได้" งาน / รางวัล / ทุน / สิทธิ์ / เงินคืน (advance fee) | "โอนค่าดำเนินการ 500 ก่อนรับทุน", "มีลิงก์ให้กรอกข้อมูลเพื่อรับสิทธิ์", "โอนช่วยจองสิทธิ์" | reward / financial_offer + money_request / credential_request / link_action |
| 4 | ขู่ (คดี / อายัด / ระงับ / ถูกแฮก / ค้างชำระ) + ให้ "แก้" ด้วยโอน / กดลิงก์ / โทรกลับ | "บัญชีถูกระงับ ยืนยันที่ลิงก์" | threat + (link_action / money_request) |
| 5 | อ้างหน่วยงาน / บทบาททางการ (ธนาคาร, ตำรวจ, แอดมินคณะ, ทะเบียน, HR) + ให้โอนเข้า **บัญชี/พร้อมเพย์บุคคล** หรือลิงก์ที่ไม่ใช่โดเมนทางการ | "แอดมินคณะ ค่าจองสอบ โอนพร้อมเพย์ 08x" | authority_claim + money_request/link_action |
| 6 | **ข้อเสนอเกินจริง** — รายได้ (วันละ ≥ 1,000 โดยไม่ต้องทักษะ/สัมภาษณ์, ชั่วโมงละ > 2 เท่าค่าแรงขั้นต่ำ), ผลตอบแทน (> ~15%/ปี, รับประกันกำไร), กู้ไม่ต้องค้ำ/อนุมัติทันที, "ผู้โชคดีได้รับวงเงิน/รางวัล" — **ไม่ต้องมีช่องทาง** (การตอบกลับคือช่องทาง) | "งานออนไลน์วันละ 10,000 ไม่ต้องสัมภาษณ์", "ผู้โชคดีได้วงเงินกู้ ธปท. 200,000" | financial_offer / reward |
| 7 | ห้ามบอกใคร / ห้ามวางสาย / ห้ามติดต่อธนาคาร | — | secrecy |
| 8 | **จ่ายเต็มก่อนเป็นทางเดียว** — "โอนเต็มก่อน", "โอนก่อนส่ง**เท่านั้น**", หรือปฏิเสธการตรวจสอบทุกทาง (ไม่รับนัด ไม่วิดีโอคอล ไม่ COD) — จากผู้ขายไม่รู้จัก (v2.2: majority 3 คน C24/C25/C29) — **ต่างจาก** "มัดจำ" / "รีบโอนก่อนนะ" ที่ยังเปิดทางตรวจสอบ = caution (C26, C28) | "ขอโอนเต็มก่อน เดี๋ยวส่งเลขพัสดุให้", "ของอยู่ต่างจังหวัด โอนก่อนส่งเท่านั้น" | money_request: โอนเต็ม/โอนก่อนส่ง + refuse_verification |
| 9 | ลิงก์ที่ตรวจไม่ได้ (shortener bit.ly/cutt.ly, TLD แปลก .xyz/.top/.cc, IP, โดเมนเลียนแบบ) + ข้อเสนอหรือคำขอใดๆ | "ลด 90% วันนี้เท่านั้น bit.ly/xxxx", "scb-verify.xyz" | link_action: url_shortener / suspicious_tld / ip_url |
| 10 | **คนไม่รู้จักขอเลขบัญชี/พร้อมเพย์ของฉัน "จะโอนให้"** — บัญชีม้าโดยไม่รู้ตัว: โอนเงิน(ที่ได้จากเหยื่ออื่น)เข้ามาแล้วอ้าง "โอนเกิน ช่วยโอนคืน" = ฟอกเงินผ่านบัญชีเรา (พ.ร.ก. บัญชีม้า 2566) หรือส่งสลิปปลอมแล้วขอของ (v2.1 — A1 & A2 blind รอบ 3 ให้ danger) | "ขอเลขบชพร้อมเพย์หน่อยคับ จะโอนค่าชีท" จากคนไม่รู้จัก | inbound_payment_offer |
| 11 | **อ้างเป็นคนรู้จัก จากเบอร์/บัญชี/ไอดีใหม่ + ขอเงิน** ("เปลี่ยนเบอร์ใหม่นะ ขอยืมเงิน 5,000 ด่วน") — สูตร borrowing scam ครบในข้อความเดียว (v2.2: majority A2/A3 บน C14; A1 ให้ caution) | "หวัดดี เปลี่ยนเบอร์ใหม่นะ ขอยืมเงิน 5,000 ด่วน เดี๋ยวคืนพรุ่งนี้" | borrowing_pretext + money_request |

**#10 ใช้เมื่อผู้ขอเป็นคนไม่รู้จัก** (สมมติฐานตั้งต้นของทุกข้อความ) — ถ้าใน Q&A ผู้ใช้ยืนยันว่าเป็นผู้ซื้อจากโพสต์ขายของตัวเอง คำแนะนำคือให้รับเงินผ่านช่องทางแพลตฟอร์ม/QR และ **ห้ามโอนคืน** ถ้าถูกอ้างว่าโอนเกิน (ให้ติดต่อธนาคาร) — verdict ของ turn ถัดไปเป็น caution + watch_for

**ที่ไม่ใช่สัญญาณ** (พบในข้อความปกติได้): มัดจำ/"รีบโอนก่อนนะ" ที่ยังเปิดทางตรวจสอบ, ทัก DM/inbox, LINE ID ของผู้ขาย, เร่ง/หมดเขต/เหลือชิ้นเดียว, ราคาถูก, ชื่อธนาคาร/แบรนด์, "ฟรี", ภาษาไม่ทางการ, ไม่แนะนำตัว, อ้างเป็นคนรู้จักโดยไม่ขอเงิน — สิ่งเหล่านี้ทำให้ได้ **caution + needs_info** ไม่ใช่ danger (v2.2: "ทักไลน์อย่างเดียว ไม่ตอบในกลุ่ม" = ดึงออกจากที่สาธารณะ → caution + [seller_reputation, sender_identity]; "จอง/สั่ง" ของถูกจากคนไม่รู้จัก = ต้องมัดจำโดยนัย → caution + [seller_identity, seller_reputation])

## 4. รายการปิด: `needs_info` (7 รหัส — caution ต้องมี ≥ 1)

| รหัส | ต้องเช็คว่า | ใช้กับ |
|---|---|---|
| `url` | ลิงก์/ช่องทางที่พูดถึงแต่ไม่เห็นปลายทาง — ไปที่ไหน | "มีลิงก์รายละเอียดกิจกรรม ลองดูนะ" |
| `sender_identity` | ผู้ส่งเป็นใคร (ไม่ระบุ/ระบบ/เพจ) | "ระบบแจ้งให้ยืนยันข้อมูลภายในวันนี้" |
| `verify_with_claimed_person` | ถามคนที่ถูกอ้าง (แม่/รุ่นพี่/เพื่อน/แอดมิน) **ผ่านช่องทางเดิม** ว่าใช่จริงไหม | "แม่โอนค่าเทอมให้ด่วน", "รุ่นพี่ฝากบอกให้โอนค่าชีท" |
| `seller_identity` | ผู้ขายเป็นใคร ร้านอะไร | โอนก่อน/มัดจำ ทุกเคส |
| `platform_policy` | ซื้อผ่านแพลตฟอร์มที่คุ้มครองผู้ซื้อ หรือโอนตรง / ร้านมีกฎจ่ายก่อนจริงไหม | โอนก่อน/มัดจำ ทุกเคส |
| `seller_reputation` | มีคนในกลุ่มเคยซื้อ / รีวิว / เครดิต | โอนก่อน/มัดจำ ทุกเคส |
| `account_name_match` | ชื่อบัญชีปลายทางตรงกับผู้ขาย/ผู้ที่อ้างไหม — ใช้เมื่อข้อความ**ระบุบัญชี**แต่ยังไม่เห็นชื่อ | "โอนมาบัญชีนี้ xxx-x-xx5678" |

**ชุดมาตรฐาน:** marketplace โอนก่อน/มัดจำ → `[seller_identity, platform_policy, seller_reputation]` · อ้างคนรู้จัก+ขอเงิน → `[verify_with_claimed_person]` (+`sender_identity` ถ้าเป็นการ "ฝากบอก") · ขอข้อมูลคลุมเครือไม่มีผู้ส่ง → `[sender_identity, url]`
**ห้าม** ใช้ needs_info เพื่อเลี่ยง danger (ถ้าเข้า 11 ข้อแล้ว ตัวตนผู้ส่งไม่เปลี่ยนอะไร) และห้ามใช้กับ safe

## 5. `watch_for` — แกนที่ 2 สำหรับข้อความที่ safe ตอนนี้แต่เป็น turn แรกของ scam

annotator **ไม่ต้อง** ติดค่านี้ (ระบบ Q&A ใช้เขียนคำแนะนำ) — มีไว้ให้เข้าใจว่าทำไม opener เป็น safe ไม่ใช่ caution:

| opener | verdict | watch_for |
|---|---|---|
| "เปลี่ยนเบอร์ใหม่นะ เซฟไว้ด้วย" | safe | ถ้าเบอร์นี้ขอยืมเงิน/โอน → โทรเช็คเบอร์เดิมก่อน |
| "ทักผิดหรือเปล่า อยากรู้จัก" / LinkedIn opener | safe | ถ้าเริ่มพูดเรื่องเงิน/ลงทุน/ของขวัญติดศุลกากร → danger |
| ~~"ทักไลน์อย่างเดียวนะ ไม่ค่อยตอบในกลุ่ม"~~ | ~~safe~~ → **caution** ตั้งแต่ v2.2 (majority) | needs_info: seller_reputation, sender_identity |
| ~~"ขอเลขบัญชีหน่อย จะโอนให้"~~ | ~~safe~~ → **danger #10** ตั้งแต่ v2.1 | (ย้ายไปข้อ 3) |

## 6. Category (บังคับเฉพาะ `danger`; caution ใส่ได้ถ้าชัด; safe = null)

เลือกตาม **กลไกที่ทำให้เสีย** 1 ค่า: `phishing_link` (ขโมยข้อมูล/รหัส ทุกช่องทาง รวมขอ OTP ทางแชท) · `impersonation_authority` (อ้างหน่วยงาน + ขู่) · `financial_fraud` (หลอกให้โอน: บัญชีม้า, ค่าธรรมเนียม, ค่าจองสิทธิ์, ซื้อของ) · `prize_scam` (รางวัล/เงินคืน/ทุน) · `loan_offer` (เงินกู้ปลอม) · `investment_scam` (ลงทุน/รายได้เกินจริง) · `romance_scam` · `borrowing_scam` (อ้างคนรู้จัก ขอยืม) · `other` (ห้ามใช้ถ้าเข้าหมวดอื่นได้)

## 7. Protocol

1. **Cluster ก่อน label:** ตัด emoji/typo/ตัวยืด/คำต่อท้าย → ข้อความเดียวกันตัดสินครั้งเดียว
2. **Blind:** annotator 2 คนตอบแยกกัน ไม่เห็นกัน ไม่เห็นตาราง calibration (ข้อ 8) จนกว่าจะส่งคำตอบ
3. **วัด κ บน verdict ก่อน** (category เฉพาะแถว danger ที่ตรงกัน)
4. **ไม่ตรง → คนที่ 3** ตัดสินโดยเห็นแค่ข้อความ; ผลบันทึกใน `annotation.final` (`resolved_by: adjudicator`)
5. **κ < 0.6 → แก้ guideline** (bump version) แล้ว blind ซ้ำชุดเดิม — ห้าม annotate tier A จนกว่า κ ≥ 0.6
6. Field ต่อ record: `verdict`, `category`, `needs_info: []`, `confidence 1-5`, `notes`; `input_form: direct|narrative`
7. PII: ข้อความผ่าน masker แล้ว; ห้ามใส่ PII ใน notes/needs_info; `<URL>` ที่ถูก mask = *มี* URL (ไม่ใช้ needs_info: url)
8. LLM ใช้ pre-label ได้ ต้องบันทึก `annotator: "llm:<model>"` และไม่นับเป็น 1 ใน 2 คน
