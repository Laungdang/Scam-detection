# Annotation Guideline — Thai Scam Detection Corpus

**Version:** 1.0 (2026-08-29)
**ใช้กับ:** ทุก record tier A (`real_thai`) และ tier S (`safe_real`) — ดู CLAUDE.md Section 10.2
**ผู้ใช้เอกสาร:** annotator 2 คนต่อ record + adjudicator 1 คน

เอกสารนี้ versioned — ทุก record บันทึก `annotation.guideline_version` ที่ใช้ตอน label ถ้าแก้ guideline ต้อง bump version และ re-annotate record ที่กระทบ

---

## 0. หลักคิดสำคัญที่สุด

**ตัดสินจาก "การขอ" ไม่ใช่จาก "คำ"**

ข้อความ scam เกือบทั้งหมดต้องการให้เหยื่อ **ทำอะไรบางอย่าง**: โอนเงิน, ให้ข้อมูล/รหัส, กดลิงก์/ติดตั้งแอป, หรือย้ายไปคุยช่องทางที่ควบคุมได้ ข้อความที่ไม่มีการขอใดๆ เลย **แทบไม่มีทางเป็น danger** ต่อให้มีคำว่า "ด่วน", "ธนาคาร", "ฟรี"

คำเร่งด่วน / ชื่อธนาคาร / คำว่าฟรี พบในข้อความปกติตลอด (flash sale, อาจารย์ทวงงาน, แม่ขอเงินค่าเทอม, SMS แจ้งยอดจากธนาคารจริง) — annotator ต้องอ่านทั้งข้อความแล้วถามว่า **"ถ้าทำตามข้อความนี้ ฉันจะเสียอะไร"**

## 1. Verdict (บังคับทุก record)

| verdict | นิยาม | เกณฑ์ตัดสิน |
|---|---|---|
| `danger` | ข้อความนี้ **มีเจตนาหลอก** ให้เสียเงิน/ข้อมูล/การควบคุมอุปกรณ์ | มี "การขอ" (ข้อ 0) **และ** มีสัญญาณหลอกอย่างน้อย 1 อย่าง (ข้อ 3) **และ** ไม่มีบริบทที่ทำให้การขอนั้นชอบธรรม |
| `caution` | ไม่แน่ใจว่าหลอก แต่ **ถ้าทำตามโดยไม่ตรวจสอบก่อน มีความเสี่ยง** | มี "การขอ" แต่สัญญาณหลอกอ่อน/ก้ำกึ่ง, หรือเป็นข้อความที่มิจฉาชีพใช้บ่อยแต่คนจริงก็ใช้ (เช่น "เปลี่ยนเบอร์ใหม่นะ" โดยไม่ขอเงิน) |
| `safe` | ไม่มีสัญญาณหลอก | ไม่มี "การขอ", หรือมีการขอแต่บริบทชอบธรรมชัดเจน (เพื่อนขอค่าข้าวคืน, ธนาคารแจ้งยอด) |

**ข้อห้าม:**
- ห้ามให้ `danger` เพราะ "ดูเหมือน SMS" หรือ "มีลิงก์" อย่างเดียว — SMS ธนาคารจริงก็มีลิงก์
- ห้ามให้ `safe` เพราะ "ภาษาสุภาพ" — scam ส่วนใหญ่ภาษาสุภาพมาก
- ไม่มี `uncertain` ใน label — ถ้าไม่แน่ใจให้ `caution` + `confidence` ต่ำ (ข้อ 5)

### 1.1 Decision procedure (ทำตามลำดับ)

```
1. ข้อความนี้ขอให้ผู้รับทำอะไรไหม?
   (โอน/จ่าย, ให้ข้อมูล/รหัส/OTP, กดลิงก์/ติดตั้ง, แอดไลน์/ย้ายช่องทาง, โทรกลับเบอร์ที่ให้)
   → ไม่มีเลย ......................................... safe
   
2. การขอนั้นมาพร้อมสัญญาณหลอกไหม? (ข้อ 3: ขู่, ล่อรางวัล, อ้างหน่วยงาน+ลิงก์, เร่ง+โอน,
   ห้ามบอกใคร, ทักผิด→ขอเงิน, เสนอกู้/ลงทุนผลตอบแทนเกินจริง, URL แปลก)
   → มีชัดเจน ≥ 1 และไม่มีบริบทชอบธรรม ................ danger
   
3. ถ้าการขอมีบริบทชอบธรรมชัดเจน (ผู้ส่งเป็นคนรู้จักจริงในบริบท, เป็น SMS แจ้งเตือน
   จากผู้ให้บริการที่ไม่ขอข้อมูล, โปรโมชั่นที่แค่บอกราคา)
   → safe
   
4. อื่นๆ (ก้ำกึ่ง) ...................................... caution
```

### 1.2 ตัวอย่างที่ต้องตอบให้ตรงกัน (calibration set)

| ข้อความ | verdict | เหตุผล |
|---|---|---|
| ส่งงานด่วนนะครับ พรุ่งนี้เช้าอาจารย์จะตรวจ | safe | ไม่มีการขอเงิน/ข้อมูล/ลิงก์ |
| ด่วน! Flash Sale ลด 50% วันนี้วันเดียว ที่ Shopee | safe | โปรโมชั่น บอกราคา ไม่ขอข้อมูล ไม่มีลิงก์แปลก |
| แม่โอนเงินค่าเทอมให้ด่วนหน่อย พรุ่งนี้วันสุดท้าย | safe | ขอเงินจริง แต่บริบทครอบครัวชอบธรรม ไม่มีสัญญาณหลอก |
| รหัส OTP ของคุณคือ 482913 ห้ามบอกรหัสนี้กับผู้อื่น | safe | SMS ระบบส่ง OTP ให้ ไม่ได้ *ขอ* OTP |
| SCB: รายการโอนเงิน 500.00 บาท ไปยัง xxx-x-x1234 เวลา 10:15 น. | safe | แจ้งเตือนธุรกรรม ไม่มีการขอ |
| บัญชีของคุณถูกระงับ กรุณายืนยันตัวตนด่วนที่ลิงก์นี้ http://scb-verify.xyz | danger | ขู่ + ขอยืนยันตัวตน + ลิงก์ปลอม |
| กสิกรไทย ยกเลิกส่ง SMS แบบลิงก์ เพิ่มความปลอดภัย มีผลตั้งแต่วันนี้ | safe | ประกาศนโยบายจริงของธนาคาร ไม่มีการขอ (record IMC25-TH ที่เดิม label danger — ต้องแก้) |
| คุณเป็นผู้โชคดีได้รับวงเงินกู้จาก ธปท. 200,000 บาท | danger | ล่อรางวัล + อ้างหน่วยงาน (ธปท. ไม่ปล่อยกู้รายย่อย) |
| หวัดดี เปลี่ยนเบอร์ใหม่นะ เซฟไว้ด้วย | caution | pattern เปิดของ borrowing scam แต่ยังไม่ขออะไร คนจริงก็ส่งแบบนี้ |
| หวัดดี เปลี่ยนเบอร์ใหม่นะ ขอยืมเงิน 5,000 ด่วน เดี๋ยวคืนพรุ่งนี้ | danger | เปลี่ยนเบอร์ + ยืมเงิน + ด่วน = borrowing scam ครบสูตร |
| ขอโทษที่รบกวน ฉันอ่านโปรไฟล์คุณบน LinkedIn อยากเรียนรู้จากคุณ | caution | wrong-number/romance opener แต่ turn นี้ยังไม่ขออะไร |
| งานออนไลน์ กดไลค์ได้เงิน วันละ 500-2,000 บาท สนใจทัก LINE @job888 | danger | เสนอรายได้เกินจริง + ย้ายช่องทาง |

## 2. Category (บังคับเมื่อ verdict ≠ safe; `null` เมื่อ safe)

เลือก **1 หมวดหลัก** ตาม "กลไกหลอกหลัก" ไม่ใช่ตามช่องทาง ถ้าหลายหมวดซ้อน ใช้ลำดับความสำคัญ: กลไกที่ทำให้เหยื่อเสียเงิน/ข้อมูลโดยตรง > กลไกเปิด

| category | นิยาม | ตัวอย่าง | **ไม่ใช่** |
|---|---|---|---|
| `phishing_link` | หลอกให้กดลิงก์/ติดตั้งแอป เพื่อขโมยข้อมูลหรือควบคุมเครื่อง — ลิงก์คือกลไกหลัก | "บัญชีถูกระงับ ยืนยันที่ลิงก์", "พัสดุตกค้าง คลิกอัปเดตที่อยู่", "อัปเดตแอปธนาคารที่ <URL>" | ข้อความที่มีลิงก์แต่กลไกหลักคืออย่างอื่น (เช่น ลงทุน → `investment_scam`) |
| `impersonation_authority` | อ้างเป็นเจ้าหน้าที่รัฐ/ตำรวจ/ศาล/สรรพากร/ธนาคาร แล้ว **ขู่** ให้ทำตาม โดยไม่ต้องพึ่งลิงก์ | "คุณมีคดีฟอกเงิน ติดต่อ DSI ที่เบอร์...", "สรรพากรแจ้งภาษีค้าง", call-center scam | อ้างธนาคาร + ลิงก์ (นั่นคือ `phishing_link`) |
| `financial_fraud` | หลอกว่ามีธุรกรรม/หนี้/ค่าใช้จ่ายผิดปกติ ให้ **โอนเงิน/จ่าย** โดยตรง | "เงินถูกถอน 50,000 โทรกลับ", "ยอดบัตรเครดิต 100,000 ยืนยันที่...", ค่าไฟค้าง, หลอกซื้อของแล้วไม่ส่ง | ขู่คดี (→ impersonation), ลิงก์ (→ phishing) |
| `prize_scam` | ล่อว่าได้รางวัล/เงินคืน/สิทธิ์พิเศษ แล้วขอค่าธรรมเนียม/ข้อมูล/กดลิงก์ | "ผู้โชคดีได้ iPhone", "รับเงินคืนค่าไฟ", "เงินเยียวยาจากรัฐบาล กดลงทะเบียน" | โปรโมชั่นจริงที่ไม่ขออะไร (safe) |
| `loan_offer` | เสนอเงินกู้ที่ไม่มีจริง (ไม่ต้องค้ำ อนุมัติไว) เพื่อเก็บค่าธรรมเนียมล่วงหน้า/ข้อมูล | "สินเชื่อ 200,000 ไม่ต้องค้ำ", "อนุมัติใน 5 นาที แอดไลน์" | ล่อว่า "ได้รับ" วงเงินเป็นรางวัล (→ prize_scam ถ้ากลไกคือรางวัล) |
| `investment_scam` | ชวนลงทุน/เทรด/งานออนไลน์ ผลตอบแทนเกินจริง | "หุ้น VIP 30%/เดือน", "กดไลค์ได้เงิน", "Forex รับประกันกำไร" | สินเชื่อ (→ loan_offer) |
| `romance_scam` | สร้างความสัมพันธ์/ทักผิด/ขอเป็นเพื่อน เพื่อขอเงินภายหลัง | "ทักผิดหรือเปล่า อยากรู้จัก", "ที่รัก ฉันติดที่ศุลกากร ช่วยโอน..." | อ้างเป็นคนรู้จักเดิม (→ borrowing_scam) |
| `borrowing_scam` | อ้างเป็นญาติ/เพื่อน/หลาน (มักบอกเปลี่ยนเบอร์) ขอยืมเงินฉุกเฉิน | "แม่ เปลี่ยนเบอร์นะ ขอยืม 5,000", "หลานประสบอุบัติเหตุ" | คนแปลกหน้าสร้างความสัมพันธ์ใหม่ (→ romance_scam) |
| `other` | scam ชัดเจนแต่เข้าไม่ได้สักหมวด | — | **ห้ามใช้เป็นถังขยะ** — ถ้าเข้าได้ ≥ 1 หมวด ห้ามเลือก other; ถ้าไม่ใช่ scam ให้ verdict=safe ไม่ใช่ other |

**บทเรียนจาก v1 (Week 4):** 44% ของ error มาจาก label `other` ที่จริงๆ เป็น `phishing_link` หรือ `safe` — ห้ามซ้ำ ถ้าเลือก other ต้องเขียนเหตุผลใน `annotator_notes`

## 3. สัญญาณหลอก (อ้างอิง 12 มิติใน `data/lexicon/scam_lexicon.yaml`)

ใช้เป็น checklist ช่วยดู — **ไม่ใช่** นับจำนวนแล้วตัดสิน

| มิติ | บ่งชี้หลอกเมื่อ | ไม่บ่งชี้เมื่อ |
|---|---|---|
| urgency | มาพร้อมการขอเงิน/ข้อมูล/ลิงก์ | โปรโมชั่น, งาน, ครอบครัว |
| money_request | ขอโอนไปบัญชี/พร้อมเพย์ที่ไม่ใช่ช่องทางทางการ, ขอค่าธรรมเนียมเพื่อ "รับ" อะไร | เพื่อนทวงเงิน, บิลจริง |
| credential_request | **ขอ** OTP/รหัส/เลขบัตร ผ่านข้อความ | ระบบ **ส่ง** OTP ให้ |
| link_action | ลิงก์ไม่ใช่โดเมนทางการ, shortener, TLD แปลก, ให้ติดตั้งแอปนอก store | ลิงก์โดเมนทางการที่รู้จัก (แต่ยังต้องดูว่าขออะไร) |
| authority_claim | อ้างหน่วยงาน + ขู่หรือ + ลิงก์ | ประกาศ/แจ้งเตือนจากหน่วยงานที่ไม่ขออะไร |
| threat | คดี/อายัด/ระงับ ที่ต้อง "แก้" โดยโอน/กดลิงก์/โทรกลับ | — |
| reward | ต้องจ่าย/ให้ข้อมูล/กดลิงก์เพื่อรับ | โปรโมชั่นที่ไม่ขออะไร |
| financial_offer | ไม่ต้องค้ำ/อนุมัติทันที/ผลตอบแทน > ~15% ต่อปี/รับประกันกำไร | ผลิตภัณฑ์การเงินจริงที่ระบุสถาบัน + เงื่อนไขปกติ |
| secrecy | ห้ามบอกใคร/ห้ามวางสาย/ห้ามติดต่อธนาคาร | — (เกือบไม่มีบริบทชอบธรรม) |
| channel_shift | ให้แอดไลน์/เทเลแกรม ID แปลก เพื่อคุยต่อ | LINE Official ของแบรนด์ที่ verify ได้ |
| relationship_lure | ทักผิด/อยากรู้จัก จากคนแปลกหน้า | — |
| borrowing_pretext | เปลี่ยนเบอร์ + ฉุกเฉิน + ขอเงิน | คนรู้จักจริงในบริบท (annotator รู้ไม่ได้ → caution) |

## 4. Tier และแหล่งที่มา (annotator ต้องเช็ค)

| tier | เงื่อนไขที่ต้องผ่านก่อน label | ถ้าไม่ผ่าน |
|---|---|---|
| A `real_thai` | เปิด `source.url` แล้ว **เจอข้อความนี้จริง** (หรือมี `consent_id` จาก form) | ย้ายเป็น tier C หรือลบ |
| S `safe_real` | เดียวกัน | เดียวกัน |
| B `real_foreign` | ไม่ต้อง annotate — weak label จาก IMC25 | — |
| C `synthetic` | ถ้าจะ review: ตอบว่า "สมจริงพอที่คนไทยจะได้รับจริงไหม" — ถ้าไม่ → `review.status=rejected` | — |
| N `narrative` | ไม่ต้อง verdict — เก็บ category + URL สำหรับ RAG | — |

## 5. Workflow และ field ที่ต้องกรอก

```json
"annotation": {
  "labels": [
    {"annotator": "A1", "verdict": "danger", "category": "phishing_link", "confidence": 5, "notes": ""},
    {"annotator": "A2", "verdict": "danger", "category": "financial_fraud", "confidence": 3, "notes": "ก้ำกึ่ง"}
  ],
  "final": {"verdict": "danger", "category": "phishing_link", "resolved_by": "adjudicator"},
  "guideline_version": "1.0"
}
```

1. **A1, A2 label อิสระ** — ห้ามดู label ของกันและกัน, ห้ามดู label เดิมจาก source (ซ่อน field `verdict`/`category` เดิมตอน annotate)
2. `confidence` 1-5: 5 = แน่ใจมาก, 3 = ตัดสินได้แต่มีข้อสงสัย, 1 = เดา — confidence ≤ 2 ต้องเขียน `notes`
3. **ตรงกัน** (verdict และ category) → `final = ค่านั้น`, `resolved_by: "agreement"`
4. **ไม่ตรง** → adjudicator (A3) ตัดสิน, `resolved_by: "adjudicator"`, บันทึกเหตุผลใน `notes` ของ A3
5. รายงาน Cohen's κ แยก verdict / category ทุกรอบ annotate (script: `ml/annotation/agreement.py` — ยังไม่เขียน)
6. κ < 0.7 → ประชุมหา pattern ของความไม่ตรงกัน → แก้ guideline → bump version → re-annotate เฉพาะ record ที่กระทบ

**LLM pre-label:** อนุญาตให้ใช้ LLM ทำ pre-label เพื่อเร่งงาน แต่ (a) annotator ต้องเห็นเป็น "ข้อเสนอ" ไม่ใช่ default ที่กด accept, (b) บันทึกใน `labels` ว่า `annotator: "llm:<model>"` และ **ไม่นับ** เป็น 1 ใน 2 คน

## 6. PII

- ก่อนเข้า corpus ทุกข้อความผ่าน `pii_masker.mask_pii(text, "strict")` — annotator จะเห็น `xxx-x-xx5678` / `<URL>` แทนค่าจริง
- ถ้าเจอ PII ที่ masker พลาด (ชื่อจริง, เลขบัญชีรูปแบบแปลก) → **หยุด** แจ้ง maintainer แก้ masker ก่อน ไม่ label ต่อ
- ห้าม copy ข้อความไปวางใน LLM ภายนอกเพื่อช่วยตัดสิน ถ้ายังไม่ mask
